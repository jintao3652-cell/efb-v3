npm run tauri dev 崩溃修复 —— Vite 监听到了 cargo 的 dll

EFB V3 · 2026-09-11 · 症状：编译进行中 dev server 被 EBUSY 打死，Tauri 报 beforeDevCommand 非零退出

一、症状

Compiling webview2-com v0.38.2
========> ] 453/455: skyboar…
Error: EBUSY: resource busy or locked, watch '…\src-tauri\target\debug\deps\skyboard_efb_lib.dll'
    at createFsWatchInstance (…/vite/dist/node/chunks/dep-Dm0c1Wj2.js:22195:17)
Emitted 'error' event on FSWatcher instance at: …
Error The "beforeDevCommand" terminated with a non-zero status code.

注意崩溃点不在编译，而在 node 侧的 fs.watch。cargo 只是恰好正在写那个 dll。

二、根因链

  1. vite.config.ts 的 server.watch.ignored 为空，Vite 递归监听整个项目根目录
  2. src-tauri/target 下有 8073 个文件（cargo 全部构建产物），逐一被挂上 fs.watch
  3. 其中 target/debug/deps/*.dll 正被 cargo 的链接器独占占用
  4. Windows 上给这种文件建 fs.watch → ERROR_SHARING_VIOLATION，libuv 映射成 EBUSY
  5. Vite 默认的 ignorePermissionErrors: true 只吞 EPERM / EACCES，不吞 EBUSY
  6. EBUSY 于是成为 FSWatcher 上的未处理 error 事件 → node 进程直接崩
  7. 子进程崩 → Tauri 报 beforeDevCommand terminated with a non-zero status code

第 5 步是关键，Vite 源码里写得很明确（dist/node/chunks/dep-*.js）：

// 只有 EPERM / EACCES 会被忽略，EBUSY 会继续往上抛
(!this.options.ignorePermissionErrors || (code !== 'EPERM' && code !== 'EACCES'))

而 Vite 自带的忽略清单里 没有 src-tauri：

ignored = ["**/.git/**", "**/node_modules/**", "**/test-results/**", cacheDir + "/**", ...outDirs]

三、量化证据

monkey-patch fs.watch，用 Vite 的 JS API 起服务，统计启动期所有被监听的路径：

src/** 的 38 次前后完全一致，这就是「HMR 覆盖没有缩水」的直接证据 —— 不是推断。

四、修复

// vite.config.ts
server: {
  port: 1420,
  strictPort: true,
  host: host || "127.0.0.1",
  hmr: host ? { protocol: "ws", host, port: 1421 } : undefined,
  watch: {
    ignored: ["**/src-tauri/**", "**/.workbuddy/**"],  // ← 新增
  },
}

这是 Tauri 官方模板的标准配置，手写脚手架的项目很容易漏。忽略整个 src-tauri 不会影响前端： Vite 只吃 src/ 与 index.html，Rust 侧的文件由 cargo 自己监听，两者互不相干。

六、顺带闭环：Rust 改动终于编译验证了

排查中发现 C:\Users\Administrator\.cargo\bin\cargo.exe（cargo / rustc 1.98.1， stable-x86_64-pc-windows-msvc）已经装好，只是不在 bash 的 PATH 里 —— 此前「本机无 Rust 工具链」的判断作废。

export PATH="$PATH:/c/Users/Administrator/.cargo/bin"
cd src-tauri && cargo check --message-format short
